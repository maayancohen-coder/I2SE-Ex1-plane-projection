# Testing strategy

This document describes how the program is tested, and which test covers which requirement of the [SRS](SRS.md).
Decisions are referred to as [D1] .. [D11] (SRS section 5).

## Tools
- **pytest**: all automated tests are in `tests/` and run with `pytest`.
- Slow tests (performance, large files) are marked `@pytest.mark.slow` and run with `pytest -m slow`.
- One test file per module: `test_nrrd_reader.py`, `test_plane.py`, `test_projector.py`, `test_video_writer.py`, `test_demo.py`.

## Test levels

### 1. Unit tests
Each module is tested on its own (NFR-4).

**NRRD reader** (`test_nrrd_reader.py`). Test files are generated inside the test (temporary folder), not stored in the repository.
- Reads every supported type: uint8, uint16, int16, uint32; raw and gzip encoding.
- Minimal volume `1 x 1 x 1`.
- Errors, each with a clear message (FR-3): missing file, a text file that is not NRRD, not 3D, a size of `1024`, an unsupported type (e.g. float), truncated data.

**Plane** (`test_plane.py`)
- Valid triangle and valid trapezoid.
- Invalid planes [D9]: not isosceles, collinear points, identical points, inverted trapezoid (`|a'a''| > |bc|`), trapezoid not on one plane.
- `TOLERANCE` boundary: a leg difference of `0.0009` is valid, `0.0011` is invalid.

**Projector** (`test_projector.py`), on small synthetic volumes with known values.
- `round_half_up`: `2.5 -> 3`, `2.4 -> 2` [D2].
- `sample`: inside `M`, outside `M` -> 0, and a negative index -> 0 (Python would silently read from the end of the array) [D1], FR-8.
- Size of `E`: `floor(Dab) + 1` rows, `round(Dbc) + 1` columns [D3].
- The apex is sampled and is a single pixel in the centre of row 0 [D4, D5].
- Orientation: the `b` side is on the left, `a` on top [D7].
- A plane completely outside `M` gives an image of zeros; a plane partly outside gives zeros only outside (FR-8).

**Normalisation** [D8]
- uint8 volumes are unchanged.
- 16-bit volume: values are mapped to `[0, 255]` with the percentiles.
- Fallback: a volume more than 99.5% empty keeps its small object; a constant volume gives zeros.

**Video writer** (`test_video_writer.py`)
- Number of frames, frame order, frame size (maximum size, even numbers), centring and black padding, 10 fps [D11], FR-10.

### 2. Known-answer tests (phantom)
`phantom_knot.nrrd` (generated by `data/make_phantom.py`) has only the values 0, 80, 160 and 255.
- Every pixel of every projection is one of these four values (nearest neighbour does not create new values) [D1].
- A plane through the centre shows a full ring of value 80 (the spherical shell).
- A plane outside the shell gives an image of zeros.
- A plane parallel to an axis gives the same pixels as the corresponding slice of the array.

### 3. Reference vs optimised implementation
The projector has two implementations:
- a **reference** implementation with plain loops, a direct translation of [ALGORITHM.md](ALGORITHM.md);
- an **optimised** implementation with numpy, for performance (NFR-1).

The reference is checked by the tests above. The optimised implementation must return **exactly the same image** as the reference for 200 random valid planes on the phantom and on MRHead.

### 4. Performance (slow)
NFR-1: average projection time of 100 planes that cross the whole of `croissant.nrrd` (500^3). The test fails below 30 fps and reports the measured fps. Reading the file and encoding the video are not included.

### 5. Demo tests (`test_demo.py`)
`Ex0.py` is run as a separate process, exactly as the lecturer runs it: `python Ex0.py file.nrrd file.csv file.mp4`.
- Valid input: the mp4 file is created; the number of frames equals the number of planes in the CSV; the frame size is even (FR-10).
- Wrong number of arguments: a usage message is printed, no traceback (FR-1).
- Missing NRRD or CSV file, CSV with no planes: a clear error message, no traceback, no mp4 file (FR-3, NFR-2).
- Invalid rows and planes: a warning with the row number for each, and a black frame in its place (FR-5).
- Timing summary: the output contains the reading time, the average time per plane with the fps, and the writing time (FR-11).
- Manual check: the demo video of the experiment is watched to confirm it looks as expected.

### 6. Portability
NFR-6: the fast tests run automatically on Windows, macOS and Linux with GitHub Actions on every push.

## Test data
| Data | Where | Used by |
|------|-------|---------|
| Small NRRD files (valid and broken) | generated inside the tests | unit tests |
| CSV files (valid and invalid planes) | `tests/data/*.csv` (stored in the repository) | plane and demo tests |
| `phantom_knot.nrrd` | generated by `data/make_phantom.py` | known-answer and comparison tests |
| Course dataset (MRHead, croissant, ...) | `data/` (not in the repository, see [data/README.md](../data/README.md)) | comparison, performance, experiment |

Planned CSV files in `tests/data/`:
- `valid_triangles.csv`, `valid_trapezoids.csv`
- `invalid_rows.csv`: wrong number of values, non-numeric values
- `invalid_planes.csv`: not isosceles, collinear, identical points, inverted trapezoid, not on one plane
- `outside.csv`: planes completely and partly outside the volume
- `no_planes.csv`: only comments and empty lines

## How to run

